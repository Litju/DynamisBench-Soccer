# Canonical signal schema v1

Issue RES-665. Code: `src/dynamisbench_soccer/signals/`. JSON Schema for the
sidecar: [`schemas/signal-bundle-meta.v1.json`](schemas/signal-bundle-meta.v1.json)
(generated by `dbs signals schema --write`, checked in CI).

## Files

One **bundle** is one trial, one event list, or one session summary:

| File | Content |
| -- | -- |
| `<stem>.parquet` | Channels as float64 columns, SI units, in the order declared in the sidecar |
| `<stem>.json` | `BundleMeta`: everything needed to interpret the samples, plus `data_sha256` of the Parquet file |

Both are OS-neutral: little-endian Parquet, UTF-8 JSON with LF endings and sorted keys,
and no absolute paths. Bundles are data, so they live in the external store (see
[data-policy.md](data-policy.md)), never in Git.

## Kinds

| Kind | Used for | Time axis |
| -- | -- | -- |
| `timeseries` | force plates, NHE / hip dynamometers, radar/laser, LPT | implicit `t0_s + i / nominal_hz`. An optional measured `time` column is allowed |
| `events` | timing gates | required columns `t_s`, `distance_m` |
| `summary` | GNSS/IMU session summaries (context only) | none (one row per session or drill) |

## Channels

Each channel declares `name` (snake_case), `quantity`, `unit`, `side`, and for force
plates `plate` and `axis`. **Units must be canonical**, so adapters convert and record
the conversion in `provenance.transforms`:

| Quantity | Unit | Quantity | Unit |
| -- | -- | -- | -- |
| force | `N` | time | `s` |
| torque | `N*m` | position (COP) | `m` |
| velocity | `m/s` | angle | `deg` |
| distance, displacement | `m` | count, dimensionless | `1` |

Force-plate rules:
* Every force channel names its `plate`.
* Bundles with more than one plate must declare `geometry.summed_force_policy`. Only
  `sum_fz_all_plates` exists in v1.
* Per-plate zeroing is recorded in `zeroing`.

## Mandatory metadata

* `test_id` is one of the 14 ontology tests.
* `data_category` is one of `empirical | analytical | synthetic | expert-adjudicated`.
* `subject.pseudonym`: never a real name. Body mass and sex are optional, and the
  birth year is the most precise age field allowed.
* `session`: id, ISO date, match-day label (`MD`, `MD-3`, `MD+2`, …), trial index.
* `device`: device class (required), plus manufacturer, model and firmware. Store only
  a *hash* of any serial number.
* `sampling.nominal_hz` (required for timeseries) and, when known, `measured_hz`.
* `geometry`: plate layout, NHE `lever_arm_m`, `knee_angle_deg`, `hip_flexion_deg`,
  `gate_height_m`, as applicable.
* `protocol`: protocol id, arm swing, sprint start mode, dynamometer action, drop height.
* `calibration[]` and `zeroing`.
* `provenance`: `created_by` (tool@version), `source_sha256` of the raw export,
  `parents[]` (bundle id and sha256 of each input bundle), and ordered `transforms[]`.
  Derived bundles always list their parents, so lineage is a hash chain from raw
  export to result.
* `vendor_reported`: vendor-computed metrics kept **outside** the channels. They are
  never reference values (DB-07).

## Determinism and integrity

* Writer options are fixed: zstd level 3, no dictionary, no statistics, 65,536-row row
  groups, Parquet format 2.6. Writing the same bundle twice, or re-writing a bundle that
  was just read, gives identical bytes. A golden SHA-256 is pinned in the tests, so a
  dependency upgrade that changes the bytes fails CI and must be reviewed.
* `read()` re-hashes the Parquet file and refuses a mismatch with `data_sha256`.
* `iter_batches()` streams selected columns in bounded chunks (8 GB host rule).

## Versioning and migration

* `schema_version` is an integer, currently `1`. Readers refuse newer versions.
* A breaking change increments the version and adds a function
  `MIGRATIONS[n](raw) -> raw_{n+1}` in `signals/io.py`, with a round-trip test from a
  stored v`n` sidecar. Old bundles are migrated on read and never rewritten in place.
* Additive optional fields do not bump the version.

## Fixtures

`signals/examples.py` provides one deterministic example per channel type: dual-plate
CMJ, NHE, hip squeeze, timing gates, radar velocity, LPT and GNSS summary. These are
**shape fixtures** for format, adapter and QC tests, not physically consistent
signals. Use the M3 analytical generators (RES-669) to verify metrics.
